# Read aloud

Read-aloud adds an action to each assistant response in the chat timeline. Choose **Read response aloud / stop playback** to request speech; while audio is being generated or played, the floating playback control offers **Stop**. Clicking the action for the active response again also stops it. It is intentionally unavailable on user messages, and it reads assistant text only—not tool output or hidden execution data.

## Setup

1. Install the plugin: `bb plugin install ./plugins/tts`.
2. In Settings → Environment variables, set `AI_GATEWAY_API_KEY` globally or in the relevant project's Advanced settings. Environment values are stored encrypted by BB and are never returned to settings clients. Read aloud resolves the request's explicit thread and uses its project override, falling back to the global value.
3. Optionally set **Vercel AI Gateway API key override** in Settings → Installed plugins → Read aloud. A non-empty plugin secret setting takes precedence over BB environment values for every thread. Clear it to use the scoped BB environment value.
4. Reload with `bb plugin reload tts` after initial configuration so plugin status reflects the global key or override.
5. For a source checkout dev loop, run `bb plugin dev ./plugins/tts` using the matching checkout's `bb` CLI; this rebuilds the frontend/backend and reloads the installed path plugin. A plugin build alone does not install new server API support into a different BB server runtime.
6. Open a thread and use an assistant message's action button (or its mobile overflow menu).

BB's current local server is single-owner: plugin HTTP `local` auth checks trusted/local Origin and requires JSON on mutations; it does not provide per-user or per-project authorization. `requirePublicThread` confirms the thread exists and is not deleted; it does not establish caller-specific project access. This plugin uses that model, so anyone able to call the authenticated local plugin route can request speech using any existing thread's project key. Do not expose this route through a public proxy or to mutually untrusted users. BB plugins are trusted server-side code. This plugin's experimental accessor is restricted to the `tts` plugin and the single `AI_GATEWAY_API_KEY` variable; thread scope is resolved server-side, never inferred from a caller-supplied project id. The effective environment value is used only to authorize a speech request and is never returned in an HTTP response or written to plugin logs. A project override applies only to threads in that project; otherwise the global value is used. BB machine environment follows its normal scope rule: a project variable, including an empty value, overrides global scope. Read aloud treats an effective empty/whitespace-only value as unconfigured rather than falling back to a less-specific key, and returns HTTP 503 for speech. A whitespace-only plugin setting is treated as absent and falls through to BB environment configuration. With no effective key, speech requests return HTTP 503 and the plugin reports needs-configuration when no global environment key or override exists. Project-only keys are checked per request and do not change plugin-wide status.

On older BB runtimes that lack the experimental environment-key accessor, the plugin still validates the thread through `bb.sdk.threads.get` and can use the plugin key override, but cannot read BB Environment variables. The manifest's SDK floor does not detect this experimental method, so do not infer support from the floor alone. The accessor is implemented in this checkout's server runtime; the installed `bb` CLI/server must be built from the same checkout (or a release containing the accessor) for environment-key use. When the method is absent, status asks for a plugin key override.

The plugin uses Vercel AI Gateway's versioned speech-model endpoint `https://ai-gateway.vercel.sh/v4/ai/speech-model` with `openai/tts-1`, the `alloy` voice, and MP3 output. It decodes the documented base64 JSON audio response into `audio/mpeg` for the browser. Gateway model/voice availability and account entitlements are controlled by Vercel; an unavailable model appears as a bounded error in the playback control. The server bounds requests to 4,000 extracted characters and decoded audio to 10 MiB, disables caching, and streams no credentials to the client. Generated text and audio are sent to Vercel AI Gateway.

Markdown is reduced to readable prose, including headings, links, inline/fenced code, lists, quotes and tables. The response text action doesn't include tool cards and related non-conversation output. Audio is fetched only on activation and uses a revocable in-memory object URL; stopping, completion, errors, and component teardown cancel or release owned playback resources.
